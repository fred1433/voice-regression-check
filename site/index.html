What changed, and what the report can and cannot say

The injected change. The LLM's first chunk arrives 500 ms later on every turn of 20 sessions; first text, first audio and bot speaking move with it. It is named here only because the scenario is synthetic. The report's diagnosis matches it.

  • Measure that changedThe LLM inference contribution: 100% of the added time. Associated metric: TTFB of ScriptedLLM#0.
  • Turns concerned100 turns over 420 ms, in 20 of 200 sessions: every turn of those sessions, and no turn elsewhere.
  • Compatible hypotheses
    Compatible with these logs, not confirmed by them.
    • The LLM service took longer to return its first chunk on these turns.
    • The requests on these turns differed (prompt length, tools, model or sampling settings).
    • The inference server queued these requests behind others (load, batching, a slower replica).
  • Missing to decide
    • server-side timings from the inference backend for these requests (queue time, prefill time)
    • which host or replica served each session
    • prompt token counts per turn (Pipecat LLMUsageMetricsData, enable_usage_metrics=True), absent from these logs

Pipecat 1.15.0 on one Apple M1 Max with 64 GB (macOS 27.2, no NVIDIA GPU): Silero VAD, faster-whisper base on CPU, qwen2.5:3b through Ollama 0.40.13, Kokoro for the voice. The caller is synthetic speech. 3 sessions, 12 turns: median 7.86 s, min 3.36 s, max 16.19 s, p95 not shown (N = 12). Nowhere near 420 ms, and not meant to be: it is a laptop.

Log analysis runs offline: the command reads two JSONL files and a policy, and downloads nothing. The terminal output and this page are both generated from report.json. To use it on your own runs, add capture/pipecat_jsonl_observer.py to a Pipecat pipeline: it writes one envelope line per Pipecat event.
