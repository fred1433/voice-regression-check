Synthetic example

1,000 synthetic turns across 200 simulated sessions, run through Pipecat's real latency observer with a scripted clock; no model runs. In the candidate, a slower simulated LLM adds 500 ms to 100 turns; the median stays at 400 ms.

What changed, and what the report cannot say

The injected change. The LLM's first chunk arrives 500 ms later on every turn of 20 sessions; first text, first audio and bot speaking move with it. It is named here only because the scenario is synthetic. The report's diagnosis matches it.

  • Measure that changedThe LLM inference contribution: 100% of the added time. Associated metric: TTFB of ScriptedLLM#0.
  • Turns over budget100 turns over 420 ms, in 20 of 200 sessions: every turn of those sessions, and no turn elsewhere.
  • Compatible hypotheses
    Compatible with these logs, not confirmed by them.
    • The LLM service took longer to return its first chunk on these turns.
    • The requests on these turns differed (prompt length, tools, model or sampling settings).
    • The inference server queued these requests behind others (load, batching, a slower replica).
  • Missing to decide
    • server-side timings from the inference backend for these requests (queue time, prefill time)
    • which host or replica served each session
    • prompt token counts per turn (Pipecat LLMUsageMetricsData, enable_usage_metrics=True), absent from these logs

Turn s004/u5: 400 ms before, 900 ms after

A real local run, as it came out

A full Pipecat 1.15.0 pipeline on one Mac, nothing in the cloud: Silero VAD, faster-whisper on CPU, qwen2.5:3b through Ollama, Kokoro for the voice. The caller is synthetic speech.

3 sessions, 12 turns, 12/12 responded: median 8.66 s, min 3.36 s, max 16.19 s, p95 not shown (N = 12). The run checks the capture on a real pipeline, not its speed.

Versions and machine

Apple M1 Max with 64 GB, macOS 27.2, no NVIDIA GPU.

STT: WhisperSTTService, faster-whisper 1.2.1, model base, on CPU. LLM: qwen2.5:3b (Q4_K_M, digest 357c53fb659c) on Ollama 0.40.13. TTS: KokoroTTSService, kokoro-onnx 0.6.1, voice af_heart.

VAD stop_secs 0.2; turn stop: Pipecat default: TurnAnalyzerUserTurnStopStrategy(LocalSmartTurnAnalyzerV3), local ONNX model.

Transport: none: ReplayInput pushes WAV frames at real time, NullOutput drops audio at real time. Startup: a fresh pipeline per session; Ollama already running with the model pulled; the first turn of each session is kept.

8 "completed with no audio" errors came from Kokoro in turns that still got a spoken reply; they are kept in the log and counted.

cd voice-regression-check
uv sync

Log analysis runs offline: the command reads two JSONL logs, their manifests and a policy, and downloads nothing. The terminal output and this page are both generated from report.json. To use it on your own runs, add capture/pipecat_jsonl_observer.py to a Pipecat pipeline and mark sessions and turns from your scenario driver (see the README).
